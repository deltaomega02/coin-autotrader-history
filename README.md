## 전체 흐름

처음에는 AI에게 가능한 한 많은 판단을 맡겼습니다.

VALKYR에서는 GPT-4o가 차트 이미지, 기술 지표, 뉴스, 공포·탐욕 지수 등을 보고 직접 `buy / sell / hold`를 결정했습니다. 이후 ARGOS에서는 AI가 만든 진입가·목표가·손절가를 코드가 실시간으로 감시하게 하면서, 판단과 실행을 조금씩 분리하기 시작했습니다.

OMNI에서는 이 구조를 더 확장했습니다. XRP 전용 OODA-R 구조에서 출발해 여러 코인을 단계별로 분석하는 파이프라인으로 발전했고, GPT-5와 Gemini를 조합하거나 거래 회고를 다음 판단에 다시 넣는 방식도 실험했습니다.

문제는 AI의 판단을 나중에 같은 조건으로 다시 검증하기 어렵다는 점이었습니다. 프롬프트와 모델을 바꾸면서 시스템은 계속 복잡해졌지만, 어떤 변화가 실제로 유효했는지 확인하기는 쉽지 않았습니다.

METIS부터 방향을 바꿨습니다. 처음에는 코드가 만든 신호를 AI가 거르는 구조, 이후에는 AI가 직접 방향을 정하는 구조를 차례로 실험했습니다. v4에서는 라이브 매매 판단에서 AI를 뺐고, v5에서는 Gemini를 다시 넣되 코드의 리스크 엔진이 AI 결정을 거부할 수 있게 했습니다. 이후 v6에서 매매 판단의 AI를 다시 제거하고 규칙 기반 구조로 옮겼습니다.

HERMES에서는 이 흐름을 더 밀어붙였습니다. 프롬프트 대신 지표와 조건을 코드에 명시하고, 백테스트 결과를 바탕으로 파라미터와 전략 구조를 바꿨습니다. KAIROS는 HERMES 신호 엔진을 BTC 한 종목과 레버리지 3배로 줄인 실행 경로를 사용했고, 별도로 변동성 돌파 모듈과 백테스트 스크립트를 만들었습니다. 다만 KAIROS 자체의 백테스트 결과나 실제 가동 기록은 남아 있지 않습니다.

ATHENA에서는 선물에서 현물로 돌아왔습니다. 매일 실행되는 DCA 자체는 코드가 담당하고, Gemini는 매주 한 번 포트폴리오 상태를 점검하는 Guardian 역할로 제한했습니다. 여기에 15분마다 위기 조건을 확인해 필요하면 Guardian을 바로 호출하는 경로도 두었습니다. AI를 매매의 직접 결정자에서 보조적인 검토자로 옮긴 셈입니다.

결국 이 프로젝트의 흐름은 **AI에게 매매 판단을 맡기는 방식에서 시작해, 코드와 백테스트로 다시 확인할 수 있는 규칙을 늘려 간 과정**에 가깝습니다.

## 보존 방식

이 저장소는 각 시점의 전체 소스 코드를 모두 모아 둔 저장소가 아닙니다.

세대마다 변화의 흐름을 확인하는 데 필요한 대표 버전만 골랐습니다. 선택한 코드는 당시 모습을 가능한 한 그대로 남겼고, 공개 저장소에 올리기 위해 비밀값, 서버 경로, 개인 금액처럼 공개하기 어려운 부분만 자리표시자로 바꿨습니다.

중간 버전이 빠져 있더라도 README에서 없는 코드를 현재 구조에 맞춰 다시 만들거나 정리하지 않았습니다. 문서와 실제 코드가 다른 경우에는 당시 실행 코드의 동작을 기준으로 설명했습니다.

7세대까지 여러 구조를 만들고 실제 운영과 백테스트를 반복했지만, **꾸준한 수익을 내는 자동매매 시스템을 만들지는 못했습니다.**
